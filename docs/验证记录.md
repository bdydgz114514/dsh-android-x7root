### 第二轮真机：启动慢 + 工作区不可用（已修）

| 问题 | 实测 | 根因 | 修复后 |
|---|---|---|---|
| 启动慢 | 热启动约 20 秒（每次启动日志都出现 `extracted 21665 entries`，即全量重写内核） | ① 完成标记缺失就一律全量补齐的保守判断；② 内部运行时补齐每次预扫整个 payload（2.2 秒）；③ 内核扫描 2.3 秒 | 用「上次成功同步的构建号」判断，同一份 APK 第 2 次起全部跳过 → **引擎就绪 3.7 秒**（连续 3 次：3962 / 3664 / 3625 ms） |
| 工作区设置不正常 | 设置里的「AI 工作区」→ 系统选择器直接提示“无法使用此文件夹”，且无补救入口 | ① Android 11+ 没有「所有文件访问」时 SAF 拒绝所有 /sdcard 目录；② 该入口只在“首次使用”权限页，装完就找不到 | 设置页「定制」标签新增 **AI 工作区** 行（含可用状态）；无权限时先给授权引导；不可写时给「去授权 / 用默认目录」；默认目录实测落到 `/sdcard/DeepSeekHarness/workspace` 且真机确认已创建可写 |

修复后真机复测（vivo V2452A / Android 16）：
- 启动日志：`internal runtime up to date, skip patch scan` + `dshroot already synced for rev=…, skip scan`
- 工作区：点「用默认目录」→ 设置页显示 `/storage/emulated/0/DeepSeekHarness/workspace`；`ls` 确认目录已创建
- 关于行显示「DSH 定制版 1.7.5-x7root.8 · 内核 0.1.6-alpha.2」

### 真机测出的两个阻塞（已修，见 CHANGELOG）

| 阻塞 | 现象 | 修复 |
|---|---|---|
| `node-addon-require-builtin` 无 android-arm64 构建 | 引擎启动即抛错退栈，WebView 一直 `ERR_CONNECTION_REFUSED` | `dsh-app-boot` 改走 `--expose-internals` 直接 require 内部模块 |
| 0.1.6 浏览器会话认证 | 引擎其实已就绪，但健康探测拿不到 Cookie → 永远"正在启动…" | App 捕获 stdout 里的 `?token=`；探测识别 303 即判定存活；WebView 带 token 首载换取 Cookie |

### 真机上确认的行为（与先前假设不同）

- **内核不在 `/sdcard/DeepSeekHarness/dshroot`**：v1.5.2 起 node 恒从内部
  `files/payload/dshroot` 读内核（避开 FUSE 上 2 万+ 文件 stat 的慢启动），
  外部目录只在内部空间不足时兜底。实测外部目录只有 `.nomedia` / `dsh-web.log` / `knowledge`。
- **无 root + 无 Shizuku 的运行模式**下，引擎正常启动，仅特权类工具不注册（符合设计）。

## 三、明确**未验证**的部分（不要当成已验证）

- **v114 / v115 没有任何真机运行时验证**：未在真机上安装运行过，因此「知识库三级降级实际生效」「APatch 机型能探测到 root」「OEM 识别在真实 ROM 上返回正确分支」都只是**静态可确认**，不是运行时确认。

- **未验证 16 KB 页大小（Android 15+ 部分设备）与 32 位设备**：这两类需要重新编译原生运行时，属已知不支持范围。
- **未验证 Shizuku 通道**：开发机上 Shizuku 始终未授权。
- **未实测**：定时任务在 Android 12+ 的精确闹钟行为、多用户/工作资料场景、平板/折叠屏布局。
