# 兼容性与机型适配（脑测 + 已修补）

> 本文件是**在没有第二台真机的情况下**，按 Android 版本 / root 方案 / 厂商 ROM / WebView / ABI 做的
> 逐项推演，并列出**已经修补**与**需要用户自己处理**的部分。
> 实测基线只有一台：**Android 14 / ColorOS（PHZ110 / MTK）/ KernelSU root / WebView 117 / arm64-v8a**。
> 未实测项均标注为「脑测」。

## 一、这次为了兼容性新加/改了什么（x7root.6）

| # | 问题 | 影响面 | 修补 |
|---|---|---|---|
| 1 | `su` 只在 Magisk/KernelSU 路径里找 | **APatch** 用户探测不到 root | `SU_CANDIDATES` 增加 `/data/adb/ap/bin/su`、`/data/adb/apd/bin/su`、`/data/local/bin/su` |
| 2 | 知识库目录写死在 `/sdcard/DeepSeekHarness` | 未授予「所有文件访问」的机型上，建目录失败 → 知识库直接不可用 | `knowledgeDir()` 改为三级降级：**公共外部目录 → 应用专属外部目录(`Android/data/…`) → 内部目录**，取第一个可写的 |
| 3 | WebView API 只补了 Iterator / `Promise.withResolvers` / `URL.parse` | **老 WebView（Chromium 90~120）** 上前端可能报错 | 追加补齐：`structuredClone`、`Object.hasOwn`、`at`、`replaceAll`、`findLast(Index)`、`toReversed/toSorted/toSpliced/with`、`Promise.any`、`Object/Map.groupBy`、`Set` 集合运算、`AbortSignal.timeout/any`（已本机 14/14 断言通过） |
| 4 | 前台服务未声明 `dataSync` 类型 | Android 14+（未来若把 targetSdk 提到 34）保活服务会抛 `SecurityException` | 清单加 `FOREGROUND_SERVICE_DATA_SYNC`（当前 targetSdk 28 下属豁免，声明以备升级） |

## 二、按 Android 版本脑测

| Android | 预期 | 状态 |
|---|---|---|
| 7.0–8.1 (API 24–27) | 无通知渠道/无 SAF 强制；存储权限即可读写 `/sdcard`。`targetSdk 28` 下无 W^X 限制，node 能从内部目录执行 | 脑测可用 |
| 9 (28) | 同上，`targetSdk 28` 正好；`MANAGE_EXTERNAL_STORAGE` 不存在，代码已按 `SDK_INT >= 30` 分支 | 脑测可用 |
| 10 (29) | 分区存储引入，但 `targetSdk 28` 走 legacy 路径，`/sdcard/DeepSeekHarness` 仍可写；W^X 只对 targetSdk≥29 生效 | 脑测可用 |
| 11 (30) | 需「所有文件访问」才能写公共目录；**未授予时**现在会降级到 `Android/data` 或内部目录 | 已修补（#2） |
| 12 / 12L (31/32) | 悬浮窗、精确闹钟收紧；代码用 `setAlarmClock`（豁免）与非精确唤醒 | 脑测可用 |
| 13 (33) | 通知需运行时权限 `POST_NOTIFICATIONS`（App 首次引导里已有该行并按需 `requestPermissions`）；媒体权限细分不影响本应用 | 已具备 |
| **14 (34)** | 实测通过：KernelSU、无障碍、截图、上传、知识库、设置页全部正常 | **已实测** |
| 15 (35) | 前台服务类型进一步收紧（已声明 #4）；`targetSdk 28` 应用仍被允许安装（Play 商店政策不适用侧载）。**16 KB 页大小**机型需原生运行时按 16 KB 对齐重编，否则 node 可能起不来 | 部分修补，16KB 待真机 |
| 16 (36) | 同上，且侧载旧 targetSdk 会有更多系统警告；未实测 | 脑测：能装，行为同 15 |

## 三、按 root 方案脑测

| 方案 | su 路径 | 状态 |
|---|---|---|
| KernelSU | `/data/adb/ksu/bin/su`（或 `/system/bin/su` 软链） | **已实测** |
| Magisk | `/data/adb/magisk/su`、`/debug_ramdisk/su` | 脑测可用（路径已覆盖） |
| APatch | `/data/adb/ap/bin/su` | 已补路径（#1），未实测 |
| SuperSU / 其他 | `/system/bin/su`、`/system/xbin/su` | 已覆盖；若其 `su` 不支持交互式 shell，会自动退回一次性 `su -c` |
| 无 root + Shizuku | 走 `app_process` + rish | 未实测（本机 Shizuku 始终未授权）；代码路径与上游一致 |
| 无 root 无 Shizuku | 仅文件类工具可用 | 设计如此，已实测（无 root 模式） |

探测顺序：先用上次成功的路径，再遍历候选表，逐个执行 `su -c id` 看是否含 `uid=0`。

## 四、按厂商 ROM 脑测

| ROM | 主要风险 | 应对 |
|---|---|---|
| ColorOS / realme UI | 静置杀后台、收不到广播 | **已实测**；保留 `android_optimize_keepalive` 工具（Doze 白名单 + appops + 待机分组） |
| MIUI / HyperOS | 「自启动」「后台弹出界面」默认关闭，杀后台激进 | 引导用户：设置→应用→自启动/省电策略→无限制；App 侧同用 AOSP 级保活 API |
| EMUI / HarmonyOS | 后台限制 + 通知折叠；无 GMS 不影响本应用（不依赖 GMS） | 同上；WebView 可能是华为自带旧版 → 依赖 #3 的 API 补齐 |
| OneUI | 休眠应用会冻结 | 引导加入「不受监视的应用」 |
| Funtouch / OriginOS、Flyme | 类似 MIUI | 同上 |
| 原生 AOSP / Pixel | 无额外限制 | 脑测最顺 |

统一的 AOSP 级保活手段（已内置）：`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 白名单、`RUN_IN_BACKGROUND/RUN_ANY_IN_BACKGROUND` appops、前台服务常驻、`setAlarmClock` 自唤醒。**厂商私有开关必须用户手动开**，App 无法代劳。

## 五、其它

- **ABI**：运行时是 `node v26.4.0 / android-arm64`，**只支持 arm64-v8a**。`checkAbiCompat()` 会在非 arm64 设备上提示。armeabi-v7a / x86 设备无法运行（需自行替换运行时）。
- **WebView**：`checkWebViewCompat()` 检测过旧/缺失时提示；配合 `mobile-patch/webview-compat.js` 的补齐，可覆盖到 Chromium ≈90。
- **屏幕**：UI 全部按 `dp` 布局，平板/折叠屏可用；未做横屏专门适配。
- **存储路径**：统一用 `Environment.getExternalStorageDirectory()`，兼容多用户 `/storage/emulated/<user>`。
- **SELinux**：`targetSdk 28` 规避了 `execve` 限制，Android 10+ 上仍可从 `/data/data/<pkg>` 执行 node；这也是**不能**把 targetSdk 提到 29+ 的原因。
